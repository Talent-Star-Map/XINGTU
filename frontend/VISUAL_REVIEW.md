# 前端交付视觉检查

每次界面改动完成前，除类型检查和构建外，必须实际打开页面进行视觉审查。构建成功、接口返回成功不能替代视觉验收。

1. 对照用户指定的参考页面或截图，检查布局、色彩、字体、节点形状、大小和留白。涉及动态效果时必须连续观察，不能仅凭静态截图。
2. 使用实际登录数据检查首次进入的默认状态、加载与空状态，以及本轮涉及的交互。
3. 检查桌面、窄屏和手机尺寸；查看标签遮挡、文字截断、内容溢出、按钮可用性。合理省略的长标题需能从详情读取完整内容。
4. 对三维图谱检查默认缓慢旋转、暂停与恢复、拖动后的多个视角、缩放、复位、筛选、点选依据和完整列表。遵守系统减少动态效果偏好。
5. 部署后在实际访问入口重复关键检查，并确认 JS/CSS 等资源能加载。保留截图、验证结果、源码提交和镜像版本以便回溯。
6. 报告检查范围及仍存在的限制。不得把有限样例、有限角度的检查描述为所有数据和视角均无问题。

个人经历图谱以 GitHub 个人主页的深色三维图谱为视觉基线：中心立方体、经历八面体、技术球体、缓慢旋转、细连线与彩色标签。生产数据按经历关系展开分支；不照搬参考页的个人资料或凭名称推断科研/工程类别。只有技能自述、没有经历依据的技术仍保留在完整列表，可点选查看。

截图可能包含个人资料；登录材料、私人截图和原文验证数据留在本机受控验证目录，不提交到 GitHub。
