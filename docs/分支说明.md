# 分支用途与合并说明

| 分支 | 内容 | 合并方式 |
| --- | --- | --- |
| `main` | 星图主系统，包含 `backend/` 与 `frontend/` | 主系统的集成分支 |
| `zdy_dev` | 主系统开发分支 | 仅将审阅通过的新增改动合入 `main`，保留主分支已有功能与配置 |
| `data_collection` | 独立的数据采集服务，包含采集器、分析与同步任务 | 在本分支维护及部署，不将整个分支直接合入主系统根目录 |
| `applet` | 独立小程序代码 | 在本分支维护及部署，不将整个分支直接合入主系统根目录 |

## 本次安全整改的整合

- 四个分支分别完成凭据历史清理及防泄露检查。
- `zdy_dev` 的两条安全整改提交通过合并整合到 `main`。冲突按主系统当前结构解决，保留主分支的运行配置与业务功能，同时补充后端镜像对用户上传目录的排除。
- 采集、小程序分支具有独立代码历史；GitHub 的 “Compare & pull request” 黄色提示仅表示最近有推送，不构成必须合并的任务。
- 不为消除提示创建空 PR、删除仍在使用的分支或强行合并独立项目。如需统一为一个目录结构，须另行规划目录、构建、部署和协作方式。

## 历史清理后的协作

协作者先备份未提交工作，再迁移或重新克隆清理后的分支，避免把旧敏感历史推回。每项主系统功能通过明确的 PR 审阅；采集服务和小程序继续在各自分支验证。

运行环境中的 JWT、邮箱、数据库和 AI 凭据不随分支合并共享，仍通过各运行环境的私有配置提供。
