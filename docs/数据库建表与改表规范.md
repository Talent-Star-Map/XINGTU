# 数据库建表与改表规范（方式B：手动 SQL，全员统一）

> 本项目数据库统一采用**方式B（手动建表）**：在 Navicat 中手动执行 SQL，**不依赖 `create_all` 自动建表**。
> 理由：手动建表**完全可控、每个人都知道建了什么、字段说明清晰**，避免"代码加了模型云库悄悄多表"的问题。
> 适用对象：所有成员（后端开发）。

## 二、保姆式创表流程（新建一张表）

### 第 1 步：写建表 SQL 文件（放到 `backend/sql/`）

每个新表在 `backend/sql/` 下建一个 `.sql` 文件，统一格式：

```sql
-- ═══════════════════════════════════════════════════════════════
-- 表名 — 一句话说明这张表干什么
-- ═══════════════════════════════════════════════════════════════
-- 用途：详细描述
-- 对应 ORM 模型：backend/database.py::XxxModel
-- 建表方式：在 Navicat 中手动执行（方式B，不参与 create_all 自动建表）
--
-- ⚠️ 变更规范：
--   · 新增/修改字段时，同步更新本文件 + database.py 对应模型
--   · 所有字段必须写 COMMENT 说明
-- ═══════════════════════════════════════════════════════════════

CREATE TABLE IF NOT EXISTS 表名 (
  id           INT PRIMARY KEY AUTO_INCREMENT COMMENT '自增主键',
  字段1        VARCHAR(100) NOT NULL COMMENT '字段说明',
  字段2        INT DEFAULT 0 COMMENT '字段说明',
  created_at   DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  updated_at   DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='表说明';
```

**字段类型速查：**

| 想存什么 | 类型 |
|---|---|
| 自增 ID | `INT PRIMARY KEY AUTO_INCREMENT` |
| 短文本（名字/标题） | `VARCHAR(50)` ~ `VARCHAR(200)` |
| 长文本（描述/正文） | `VARCHAR(500)` ~ `VARCHAR(2000)` |
| 非常长 | `LONGTEXT` |
| 整数（数量/开关/年龄） | `INT` |
| 小数（评分/薪资） | `DECIMAL(10,2)` |
| 开关（0/1） | `TINYINT DEFAULT 0` |
| 时间 | `DATETIME` |
| JSON | `JSON` |
| 必填 | 加 `NOT NULL` |
| 不填则默认 | 加 `DEFAULT xxx` |

### 第 2 步：在 Navicat 中执行

1. 打开 **Navicat** → 连接到 `180.76.227.159:3308`（密码 `Xingtu123`）
2. 双击 `xingtu` 数据库 → 打开「查询」→ 新建查询
3. 把第 1 步的 SQL 粘贴进去 → 点「运行」
4. 左下角显示「执行成功」即建表完成

### 第 3 步：代码里加 ORM 模型（`database.py`）

在 `database.py` 里加对应的模型类。**注意：新表用「独立 Base」，不放进 `create_all` 的 `Base` 里。**

```python
# 每个手动建表的表单独用一个 Base，避免被 create_all 自动建
XxxBase = declarative_base()

class Xxx(XxxBase):
    """表名 — 字段说明（每个字段一行注释）"""
    __tablename__ = 'xxx'
    id = Column(Integer, primary_key=True, autoincrement=True)
    ...
```

> 判断标准：**想让这张表被 `create_all` 自动建** → 继承 `Base`；**手动建** → 继承独立的 `XxxBase`。
> 本项目统一方式B，新表都继承独立 Base。

### 第 4 步：代码里直接用 ORM 访问

```python
from database import Xxx, get_session
session = get_session()
rows = session.query(Xxx).all()
session.close()
```

## 三、保姆式改表流程（给已有表加字段 / 改字段）

### 第 1 步：在 Navicat 里写 ALTER 语句

```sql
-- 加一个字段
ALTER TABLE 表名 ADD COLUMN 新字段名 VARCHAR(100) DEFAULT '' COMMENT '字段说明';

-- 示例：给 jobs 表加一个 job_source 字段
ALTER TABLE jobs ADD COLUMN job_source VARCHAR(50) DEFAULT '' COMMENT '岗位来源：boss/lagou/manual';
```

```sql
-- 修改字段类型/默认值
ALTER TABLE 表名 MODIFY COLUMN 字段名 VARCHAR(200) DEFAULT 'xxx' COMMENT '新的说明';

-- 示例：把 experience 从 VARCHAR(50) 改成 VARCHAR(100)
ALTER TABLE jobseekers MODIFY COLUMN experience VARCHAR(100) DEFAULT '' COMMENT '工作经验';
```

```sql
-- 删字段（⚠️ 会丢数据，谨慎）
ALTER TABLE 表名 DROP COLUMN 字段名;
```

### 第 2 步：同步更新两处

改了字段后，**必须同步更新**，否则代码和库不一致会报错：

1. **`backend/sql/` 里对应的建表 SQL 文件** —— 把新字段也写进 `CREATE TABLE`（保证新人照着建出来是全的）
2. **`backend/database.py` 对应模型** —— 加对应的 `Column`

### 第 3 步：在 Navicat 运行 ALTER 语句

同「创表第 2 步」，粘贴运行即可。

## 四、⚠️ 铁律：改表/建表必须做的事

| 项目 | 要求 |
|---|---|
| **提前告知** | 建表/改表**前**在群里说一声：「我要建 `xxx` 表 / 给 `yyy` 表加 `zzz` 字段，结构如下…」，确认后再动 |
| **写字段说明** | 每个字段必须有 `COMMENT`（表字段说明） |
| **同步三处** | 建表 SQL 文件 + `database.py` 模型 + Navicat 里的实际表，三者字段必须一致 |
| **不删数据** | 除非明确确认，否则不 DROP TABLE / DROP COLUMN / DELETE 数据 |
| **备份** | 动关键表前，建议先在 Navicat 导出备份（右键表 → 导出） |

## 六、判断：这个表该用 create_all 还是手动？

| 场景 | 推荐 | 理由 |
|---|---|---|
| **核心业务表**（需求稳定） | 手动 SQL（方式B） | 完全可控 |
| **演示/临时表** | 手动 SQL（方式B） | 统一习惯 |
| **代码里新增的辅助表** | 手动 SQL（方式B） | 避免"悄悄建表" |

> 本项目**统一方式B**。`database.py` 的 `Base` 只保留最早期那几张核心表（jobseekers/enterprises/admins 等），新表一律手动。
