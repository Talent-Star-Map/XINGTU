## 第一部分：赛题关键要点提取

### 一、时代背景（为什么这个赛题现在被提出来？）

| 背景要素 | 原文对应 | 翻译成人话 |
|---|---|---|
| **人口红利→人才红利转型** | "从'人口红利'向'人才红利'转型的关键期" | 以前靠人多，现在靠人精。国家不再需要"什么都会一点的人"，需要"在特定领域深入的人" |
| **新质生产力 + AI+ 行动** | "'新质生产力'概念的提出、'人工智能+'行动的深入实施" | AI 不再是锦上添花，而是各行各业的基础设施 |
| **数字经济蓬勃发展** | "数字经济的蓬勃发展" | 互联网/IT 行业高速变化，新岗位新技术层出不穷 |
| **技术迭代 > 人才培养** | "技术迭代速度远超人才培养周期" | 学校教的东西还没毕业就过时了，企业需要的人学校培养不出来 |

### 二、核心矛盾（赛题要解决什么问题？）

```
企业端：招不到合适的人
          ↓
       结构性矛盾
          ↑
求职端：不知道学什么、往哪走
```

| 矛盾 | 具体表现 |
|---|---|
| **企业端** | 新兴岗位"招不到合适的人"，JD 写不清楚，技能要求跟不上市场 |
| **求职端** | 职业路径模糊，技能需求动态性强，不知道学什么才不会被淘汰 |
| **技术端** | 传统关键词匹配无法感知技术趋势，无法回答"技术A的爆发会导致岗位B产生什么新技能需求" |

### 三、赛题强制要求使用的核心技术（⚠️ 这是硬性要求，不是建议）

> **原文关键段落：**
> "随着大模型的强语义理解与信息抽取能力、知识图谱对复杂关系的结构化表达能力，以及多源数据融合与交叉验证技术的深度应用，构建一个能够自我进化的'人才能力大脑'，实现从'静态画像'向'动态感知'的跨越已成为可能。本赛题聚焦'数据驱动+大模型+知识图谱'核心技术方向，重点围绕三大核心难题展开攻关"

#### 🚨 这段话不是在描述背景，是在指定技术清单

评分标准"技术创新性（25 分）"明确写着：

> **"创新性应用大模型、知识图谱、RAG 等技术……得 25 分"**
> **"未应用指定相关技术……扣 15-25 分"**

所以以下四项技术是**必须用**的，缺一项就扣分：

#### 赛题指定的四项核心技术

| 编号 | 指定技术 | 原文对应 | 你们系统哪部分用 | 不用会怎样 |
|---|---|---|---|---|
| **①** | **大模型（LLM）** | "大模型的强语义理解与信息抽取能力" | JD解析、技能提取、匹配分析、学习路径生成 | ❌ 技术创新性直接扣 10-15 分 |
| **②** | **知识图谱** | "知识图谱对复杂关系的结构化表达能力" | 岗位→技能关系展示、全景图谱可视化 | ❌ 全景图谱就是知识图谱的体现 |
| **③** | **多源数据融合与交叉验证** | "多源数据融合与交叉验证技术的深度应用" | 多源采集、质检Agent交叉验证、抄袭检测、通胀检测 | ❌ 这是"幻觉防控"的核心，不做到不了 25 分档 |
| **④** | **RAG（检索增强生成）** | 评分标准里明确写到的 | 技能词典检索 + LLM 提取，先查词典再让 LLM 提取，减少幻觉 | ⚠️ 赛题评分标准里点名了这项 |

#### 每项技术在你们系统里的落地

```
① 大模型 → DeepSeek API
   ├─ JD解析 Agent：从JD文本提取技能
   ├─ 匹配 Agent：对比简历技能和岗位技能
   ├─ 趋势 Agent：判断新岗位、检测变化
   └─ 学习路径 Agent：生成学习计划

② 知识图谱 → react-force-graph-2d / 图数据库
   ├─ 节点：岗位、技能
   ├─ 边：岗位→需要→技能
   └─ 视图：按技术栈切换、按级别切换

③ 多源数据融合与交叉验证 → Python 爬虫 + 质检 Agent
   ├─ 源1：Boss 直聘
   ├─ 源2：拉勾
   ├─ 源3：GitHub Jobs
   └─ 质检Agent：同一个技能在 ≥2 个来源出现才收录

④ RAG → 技能词典检索
   ├─ 先查技能词典（数据库里已有的标准化技能）
   ├─ 再让 LLM 从 JD 里提取
   └─ 只收录词典里存在或 LLM 高置信度的技能
```

#### "自我进化的人才能力大脑"具体指什么？

| 关键词 | 字面意思 | 你们要实现的 |
|---|---|---|
| **自我进化** | 系统能自动感知变化并更新自己 | 定时采集 → 自动对比 → 发现变化 → 更新图谱 |
| **人才能力大脑** | 一个能"思考"岗位和技能关系的智能系统 | 不是简单的数据库查询，而是基于大模型的理解和推理 |
| **静态画像→动态感知** | 从"一次性的描述"变成"持续追踪" | 传统 JD 是静态的，你们的数据是持续更新、反映最新趋势的 |

### 四、赛题三大核心攻关难题

这是赛题最核心的三段话，**你们的系统必须对应解决这三个问题**：

#### 难题①：新岗位发现与既有岗位能力动态更新

> **原文：** "如何从海量多源数据中精准发现并定义新兴岗位，更新既有岗位的能力要求，构建可动态更新的岗位能力图谱"

**拆解：**

| 子问题 | 要求 |
|---|---|
| **新岗位发现** | 识别市场上正在萌芽但尚未被标准化或逐渐兴起的新岗位 |
| **新岗位定义** | 生成岗位名称、核心职责、必备技能、加分技能、典型行业应用场景 |
| **既有岗位更新** | 针对现有岗位，识别其能力要求的变化 |
| **更新说明** | 提供更新说明及数据源，明确标注新增/删除/修改的能力项 |
| **人工优化** | 支持人工优化与动态更新演化 |

#### 难题②：数据时滞、噪音、抄袭与幻觉防控

> **原文：** "如何解决招聘数据中的'时滞'、'噪声'与'抄袭'问题，并通过技术手段有效防控 AI 生成内容'幻觉'的产生"

**拆解：**

| 问题 | 含义 | 举例 |
|---|---|---|
| **时滞** | JD 写的技能要求已经过时了 | JD 还在写"要求 Hadoop"，实际行业都在用 Flink/Spark |
| **噪音** | 大量重复/低质量的数据干扰判断 | 同一家公司发 10 条内容基本一样的 JD |
| **抄袭** | 小公司直接复制大公司的 JD | 拿到"精通 K8s 架构设计"，实际只用 Docker |
| **通胀** | 技能要求虚高 | 招初级岗写"5 年经验精通架构设计" |
| **幻觉** | AI 编造不存在的技能 | LLM 提取了 JD 里根本没有提到的技术 |

#### 难题③：高精度简历解析与人岗差距分析

> **原文：** "如何实现高精度的简历解析与细粒度的人岗差距分析"

**拆解：**

| 要求 | 具体 |
|---|---|
| **简历解析** | PDF/Word 上传，提取技能要素，准确率 ≥ 90% |
| **多维度匹配分析** | 技能/经验/薪资/地区/学历/方向等多维度 |
| **差距分析** | 输出你缺什么技能、差距有多大 |
| **改进建议** | 针对性的能力提升建议 |
| **学习路径规划** | 从入门到掌握的完整学习路线 |

### 五、赛题要求实现的系统全流程

> **原文：** "形成一套从'新岗位发现与定义'、'既有岗位能力动态更新'到支持'全景图谱可视化'、实现'人岗匹配诊断'、最终提供'针对性改进建议与岗位学习路径规划'的系统"

**完整链路：**

```
多源数据采集
    ↓
新岗位发现与定义  ← →  既有岗位能力动态更新
    ↓
能力图谱构建与可视化（技能级粒度）
    ↓
简历解析（PDF/Word）  →  人岗匹配诊断  →  差距分析
    ↓
针对性改进建议 + 岗位学习路径规划
```

**评分标准里这对应"作品完整性"的 30 分——全流程跑通才有分，断一环就扣分。**

## 第二部分：痛点分析——走进用户、走进赛题

> 你们团队是大二学生，没有经历过求职和招聘，所以对用户的痛点只能靠猜。下面我带你们"走进"两类用户的真实世界。

### 用户画像一：求职者 / 学生（20-30 岁）

#### 🧑 场景 1：迷茫的准毕业生

```
"我学计算机的，但 Java、前端、大数据都学过一点，
不知道毕业能做什么。看招聘网站，岗位名字都差不多，
点进去看 JD，每个都要求一堆技能，也不知道自己够不够。
到底哪个方向适合我？我现在开始准备还来得及吗？"
```

| 痛点 | 本质 | 现有方案为什么不行 |
|---|---|---|
| **岗位模糊** | 同一个名字实际是不同的岗位 | 招聘网站只有关键词搜索，"数据分析师"和"数据工程师"分不清 |
| **看不清趋势** | 不知道未来什么技能值钱 | 没有动态更新的能力图谱，全靠道听途说 |
| **自我认知模糊** | 不知道自己技能值多少钱 | 没有"以能力而非经历"的匹配工具 |
| **反馈黑洞** | 投了简历没回音，不知道差在哪 | 招聘网站只告诉你"不合适"，不告诉你怎么改 |
| **学习路径不明** | 知道要学但不知道学到什么程度够 | 培训机构的课和真实岗位脱节 |

#### 🧑 场景 2：焦虑的研一学生

```
"导师说 AI 很火，让我往这个方向靠。但我看了 AI 工程师的 JD，
有要 NLP 的、有要 CV 的、有要推理部署的……
我一个研一学生不可能全都学。
到底选哪个细分方向？哪个方向未来 2-3 年还会热？
我怕学了半天，毕业时这个方向已经凉了。"
```

| 痛点 | 本质 | 现有方案为什么不行 |
|---|---|---|
| **方向选择焦虑** | 怕选错方向，时间投入打水漂 | 没有趋势预测工具，只能靠赌 |
| **信息不对称** | 不知道市场未来需要什么 | 招聘数据是静态的，没有"变化"的维度 |

#### 他们的核心诉求

```
求职者最怕的不是"没岗位"
而是"不知道自己差在哪、该往哪走"

他们要的：
  ├─ 一张地图——告诉我现在在哪、能去哪、怎么去
  ├─ 一面镜子——告诉我跟目标岗位差什么
  └─ 一条路径——告诉我怎么补上差距
```

---

### 用户画像二：企业 HR / 招聘负责人（25-40 岁）

#### 🏢 场景 1：不知道招什么人的 HR

```
"公司要招一个'AI 应用开发工程师'，但我连这个岗位应该会什么
都不确定。网上搜了一下，每家写的都不一样：
A 公司要 Python+Flask
B 公司要 LangChain+大模型 API
C 公司要 RAG 架构+向量数据库

到底哪个才是对的？我都写进 JD 里？那谁干得了啊？
而且我写个 JD 发出去，3 个月后技术又变了，是不是又得重写？"
```

| 痛点 | 本质 | 现有方案为什么不行 |
|---|---|---|
| **JD 定义难** | 新岗位没有标准 JD，不知道怎么写 | 只能抄同行，导致所有 JD 同质化 |
| **追不上变化** | 岗位技能要求几个月一变 | JD 发布后就是静态的，不会自动更新 |
| **缺乏数据** | 不知道市场薪资水平、技能分布 | 全靠经验拍脑袋 |

#### 🏢 场景 2：做人才战略的管理者

```
"我们公司今年要搞 AI 转型，技术总监说要招'AI 平台工程师'。
但这个岗位去年还没有，我想知道：
① 别的公司这个岗位到底要求什么技能？
② 给多少薪资比较合理？
③ 这个岗位的技能要求最近半年有什么变化？

我现在全靠拍脑袋做决策。"
```

| 痛点 | 本质 | 现有方案为什么不行 |
|---|---|---|
| **缺市场情报** | 人才决策没有数据支撑 | 没有行业级的能力数据和分析 |
| **无法预测趋势** | 不知道哪些技能在涨/在跌 | 没有时间维度的技能需求分析 |

#### 他们的核心诉求

```
HR 最怕的不是"招不到人"
而是"定义不清楚自己要什么人"

他们要的：
  ├─ 一个标准——新岗位的 JD 应该怎么写
  ├─ 一面镜子——我的 JD 跟市场比有没有问题
  └─ 一张报表——哪些技能在涨、薪资怎么定
```

## 第三部分：赛题核心关键词解析

> 赛题里出现的高频词，统一理解，方便团队对齐

| 关键词 | 在赛题中的含义 | 你们要实现的 |
|---|---|---|
| **多源异构数据** | 多个不同来源、不同格式的数据 | 招聘网站 + GitHub + 技术博客 + 论文 |
| **大模型** | 具备强语义理解能力的 AI 模型 | DeepSeek API / 通义千问 API |
| **知识图谱** | 用节点和边表达的"关系网" | 岗位→技能→技能的关系图 |
| **RAG** | 检索增强生成（先检索再回答） | 检索技能词典 + LLM 提取，减少幻觉 |
| **时滞** | 数据过时了 | 标记采集时间，对比不同时期的数据 |
| **噪音** | 无关/错误的数据 | 去重 + 相似度过滤 |
| **抄袭** | JD 互相复制 | 检测相似度，标记疑似抄袭 |
| **通胀** | 技能要求虚高 | 统计分布，标记偏离均值的异常值 |
| **幻觉** | AI 编造不存在的信息 | 交叉验证 + 置信度评分 + 原文溯源 |
| **交叉验证** | 多源互相校验 | 同一技能在 ≥2 个来源出现才收录 |
| **动态演化** | 系统能自动感知变化并更新 | 定时采集 + 自动对比 + 推送更新通知 |
| **技能级粒度** | 细到具体技能而非大类 | 不是"编程"而是"Java/Spring Boot/K8s" |
| **全景图谱** | 完整展示所有岗位-技能关系 | 可交互的力导向图 / 知识图谱可视化 |

> - 智能系统（嵌入式、ROS、自动驾驶）
> - 物联网（IoT、边缘计算）
> - 云计算/云原生（K8s、Docker、DevOps）

> - 前端/移动开发
> - 网络安全

### 二、核心功能要求（四项，缺一扣分）

#### 功能①：新岗位发现与定义

| 编号 | 硬性指标 | 验收标准 |
|---|---|---|
| ①-1 | 识别市场上正在萌芽的新岗位 | 至少输出 **1 个** 新岗位案例 |
| ①-2 | 生成的岗位定义必须包含：**岗位名称、核心职责、必备技能、加分技能、典型行业应用场景** | 缺一项都不算完整 |
| ①-3 | 支持人工优化 | 页面/接口允许用户手动修改 |
| ①-4 | 支持动态更新 | 系统持续追踪，变化时自动更新 |

#### 功能②：既有岗位能力动态更新

| 编号 | 硬性指标 | 验收标准 |

### 一、作品完整性（30 分）

#### 评委到底在检查什么？

```
评委拿到你的系统，心里只有一个问题：
"从数据采集到最终的岗位建议，链路能不能完整跑一遍？"
```

**他们不是看你某个功能做得多厉害，而是看有没有断链。**

#### 完整链路 = 满分（30 分）

```
多源数据采集
    ↓
新岗位发现与定义  ← →  既有岗位能力更新
    ↓
能力图谱动态展示（技能级粒度）
    ↓
简历解析（PDF/Word）
    ↓
精准匹配与差距分析
    ↓
改进建议 + 学习路径
```

**每段链路都要有输入→处理→输出的完整演示，不能跳步。**

#### 扣分档位逐条分析

| 分数 | 扣分条件 | 翻译成人话 | 你们怎么避免 |
|---|---|---|---|
| **30 分（满分）** | 全流程闭环 + 技能级全景图谱 + 人工优化 + 系统可部署运行 | 所有功能都在、能跑、能展示 | ✅ **对照核对清单，逐项检查** |
| **25-15 分（扣 5-15）** | 核心功能齐全但流程衔接不畅或次要功能缺失 | 每个功能单独看都有，但串不起来 | ✅ **提前做全流程联调，走通每一段** |
| **15-0 分（扣 15-30）** | 核心功能缺失（如新岗位发现没有）或系统部署不了 | 缺了大项 | ✅ **新岗位发现、既有岗位更新、图谱、匹配，四项一个不能少** |

#### 🚨 最常见的扣分点（你们的避坑指南）

| 扣分陷阱 | 为什么容易中招 | 怎么避免 |
|---|---|---|
| **新岗位发现"看起来像硬凑的"** | 没有真实数据支撑，评委一眼就看出来 | 用真实数据展示：某个岗位从 0 到 N 的增长曲线 |

| **简历解析只支持纯文本** | PDF/Word 解析失败了 | 提前测试 PDF 和 Word 格式 |
| **部署说明不清晰** | 评委想跑跑看但跑不起来 | Docker Compose 一键启动，写清楚步骤 |

#### 评委在找什么？

```
评委看的是：
"这个系统除了调了个 API，还有没有自己的技术设计？"

三个关键技术必须用上：**大模型** ✅、**知识图谱** ✅、**RAG** ✅

| **② 方案有突破性且可行** | "核心技术方案具备突破性与可行性" | 多 Agent 交叉验证 + 多源数据融合，技术上能实现 |
| **③ 效果显著** | "技术应用效果显著" | 用测试数据证明：准确率提升、新岗位成功发现、错误率下降 |

#### 评分档位逐条分析

| 分数 | 条件 | 对应的技术方案 |
|---|---|---|
| **25 分（满分）** | 突破传统 + 效果显著 + 幻觉防控完善 | ✅ 多Agent交叉验证 + 多源融合 + 置信度评分 + 溯源 |
| **20-15 分（扣 5-10）** | 用了大模型/图谱等技术，但没突破传统模式 | ⚠️ 只是用大模型替代了关键词匹配，没有自己的设计 |
| **10-0 分（扣 10-15）** | 没有解决幻觉等核心问题 | ❌ 调了个 API 就交差了，没有任何防控机制 |

#### 你们的创新方案（直接对标满分档）

```
传统方案：一个关键词匹配 → 输出结果
               ↓
你们的方案：
  ├─ 采集Agent 1（爬 Boss 直聘）     ← 多源

  │   同一技能在 ≥2 个来源验证才收录
  │   置信度 < 0.7 标记为待确认
  │   每个技能附带"原文依据"
  │
  ▼
  ├─ 趋势Agent（新岗位发现 + 变化检测）← 🌟 核心创新

  │   发现"从0到N"的新岗位

  │
