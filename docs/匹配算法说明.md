## 1. 总体架构

匹配引擎采用 **三阶段流水线 + 反馈闭环** 架构：

```
┌─────────────────────────────────────────────────────────────┐
│ 阶段① 全量计算（match_one）                                  │
│                                                             │
│   岗位 ──┬── ①技能匹配  TF-IDF + 四级分档 + 核心技能增益      │
│          ├── ②经验匹配  高斯衰减                              │
│   求职者 ─┼── ③学历匹配  等级映射                              │
│          ├── ④地域匹配  城市层级                               │
│          └── ⑤薪资匹配  双向覆盖率 + 高斯衰减                  │
│                                                             │
│   基础总分 = Σ(维度分 × 权重)  ← MCDM 多准则加权决策           │
│   调整项   = 核心技能惩罚 + 生态链 + 一致性 + 红旗 + 均衡性     │
│   （技能门槛：无技能交集的配对在此阶段被过滤）                   │
├─────────────────────────────────────────────────────────────┤
│ 阶段② 池内归一化（apply_pool_normalization）                  │
│                                                             │
│   同岗位候选人池内 z-score → tanh 压缩 → ±6 分相对排位微调     │
├─────────────────────────────────────────────────────────────┤
│ 阶段③ 落库（upsert match_records）                           │
│                                                             │
│   pending 记录：先清后写                                      │
│   accepted/rejected 记录：保留状态，仅刷新分数                 │
└─────────────────────────────────────────────────────────────┘
                             │
                             ▼
┌─────────────────────────────────────────────────────────────┐
│ 反馈闭环（calibrate_weights_from_feedback）                   │
│                                                             │
│   HR accept/reject 历史 → 维度区分度法 → 学习五维权重          │
│   → 下次批量匹配自动使用新权重                                 │
└─────────────────────────────────────────────────────────────┘
```

**触发方式：**

| 方式 | 命令/接口 |
|---|---|
| API 触发（前端"重新匹配"按钮） | `POST /api/enterprise/run-match` |
| CLI 触发 | `cd backend && python -m services.match_engine` |
| 权重校准 | `POST /api/enterprise/calibrate` |
| 查看当前权重 | `GET /api/enterprise/match-weights` |

## 2. 数据解析层（健壮性设计）

匹配的原始数据是中文自由文本，解析层负责把脏数据转成结构化数值。**所有解析函数容忍多种表达方式，解析失败返回 None（中性处理），绝不抛异常。**

| 函数 | 职责 | 支持的输入示例 |
|---|---|---|
| `split_skills` | 技能串拆分 | 分隔符：`,` `，` `、` `;` `；` `/` `\|` `｜` |
| `parse_skills` | 技能归一化 | 转小写、去空白、去重 |
| `parse_years` | 提取经验年数 | `"4年"` `"3-5年"` `"5年+"` `"三年"` `"应届"→0` |
| `parse_exp_range` | 解析经验区间 | `"3-5年"→(3,5)` `"5年+"→(5,None)` `"应届"→(0,1)` |
| `parse_salary_k` | 解析薪资为 K 单位 | `"30K-50K"` `"2万-3万"→(20,30)` `"面议"→(None,None)` |
| `parse_edu_level` | 学历→等级 | 博士=5 硕士=4 本科=3 大专=2 高中=1 未知=0 |

**中文数字处理**：`_CN_NUM` 映射表把 `"三年以上"` 归一化为 `"3年以上"` 后再走正则提取；`_normalize_range_text` 把全角 `～` `—` `–` `至` 统一为半角 `-`。

## 3. 五维度评分算法

每个维度输出 0-100 的整数分，统一遵守 **保底线 FLOOR=20、天花板 CEIL=92** 的设计：

- 保底：避免"某维度缺失=0 分"对总分的极端惩罚（信息缺失 ≠ 完全不匹配）
- 天花板：完美匹配也留 8 分空间，防止分数饱和导致无法区分优秀候选人

### 3.1 技能匹配（默认权重 0.40）— 核心维度

**三层机制叠加：TF-IDF 加权 × 核心技能分级 × 四级匹配分档。**

#### （a）TF-IDF 权重

```
idf(skill) = log(1 + N / (1 + df(skill)))
```

- N = 岗位总数，df = 要求该技能的岗位数
- **稀有技能**（少数岗位要求，如 K8s）→ IDF 高 → 匹配到价值大
- **大众技能**（所有岗位都要求，如 Git）→ IDF 低 → 匹配到价值小
- 批量计算前由 `compute_idf_weights()` 对全部岗位预计算

#### （b）核心技能分级

岗位技能列表**前 1/3 视为核心技能**（`core_threshold = max(len//3, 1)`），权重乘以 2.0 增益。核心技能缺失会额外计入 `core_miss_count`，触发调整项中的硬门槛惩罚（见第 4 节）。

#### （c）四级匹配分档

对岗位要求的每个技能，按匹配质量递减压权：

| 档位 | 判定条件 | 得权 | 示例 |
|---|---|---|---|
| L1 直接匹配 | 技能名完全一致（忽略大小写） | 1.0 | `python` ↔ `python` |
| L2 同义词 | 命中 `skill_synonyms.SYNONYM_MAP` | 0.9 | `k8s` ↔ `kubernetes` |
| L3 子串包含 | 一方是另一方子串（≥4 字符） | 0.7 | `pytorch` ⊂ `pytorch框架` |
| L4 邻近技能 | 命中 `skill_synonyms.ADJACENT_SKILLS` | 0.45 | JD 要 K8s，求职者有 Docker |
| 无匹配 | 以上皆否 | 0 | — |

L3 子串包含带**双重防误判**：短词（<4 字符，如 `js`⊂`json`）不判；黑名单对（`java` ⊄ `javascript`，子串成立但语义不同）不判。

#### （d）汇总公式

```
单技能权重  w = idf × core_bonus        （核心 ×2.0，普通 ×1.0）
匹配率      ratio = Σ(命中档位得权 × w) / Σw
技能分      score = 20 + ratio × (92 − 20)   → 区间 [20, 92]
```

### 3.2 经验匹配（默认权重 0.20）— 高斯衰减

对岗位经验区间 `[lo, hi]` 与求职者年数 `y`：

```
区间内:   中点 → 92，边缘 → 80（线性梯度）
          score = 92 − |y−mid|/half_range × (92−80)

低于下限: sigma = max(lo/3, 0.5)          ← 严格化：能力不足衰减快
          score = 20 + exp(−d²/2σ²) × (80−20)，d = lo−y

高于上限: sigma = max((hi−lo)/2, 1)       ← 宽容：overqualified 不是硬伤
          同高斯衰减
```

设计意图：**欠经验比超经验惩罚更重**（σ 更小），因为能力不足是硬伤、资历过剩是次要问题。

### 3.3 学历匹配（默认权重 0.15）— 等级映射

等级差打分表（req = 要求等级，user = 求职者等级）：

| 情形 | 分数 |
|---|---|
| JD 无要求 | 75 |
| 求职者学历未知 | 50 |
| 刚好满足（diff=0） | 88 |
| 高一级（diff=+1） | 92 |
| 高两级及以上 | 92（overqualified 不额外加分） |
| 低一级 | 65 |
| 低两级 | 42 |
| 低三级及以上 | 20（保底） |

### 3.4 地域匹配（默认权重 0.15）— 城市层级

| 情形 | 分数 |
|---|---|
| 远程/不限（任一方） | 75 |
| 同城 | 90 |
| 同省不同城（查 `CITY_PROVINCE` 映射表） | 72 |
| 信息缺失 | 55 |
| 不同省 | 25 |

### 3.5 薪资匹配（默认权重 0.10）— 双向覆盖率 + 高斯衰减

对岗位区间 `[j_min, j_max]` 与求职者期望 `[s_min, s_max]`（统一 K 单位）：

```
有重叠:   overlap = min(j_max,s_max) − max(j_min,s_min)
          coverage = overlap / min(job_range, seeker_range)
          score = 50 + coverage × (92−50)
          → 求职者期望区间完全被岗位覆盖 → 92 分

无重叠:   gap = 两区间间距
          score = 20 + exp(−gap²/2σ²) × (50−20)，σ=10K
          → 刚擦边 gap→0 时 50 分，连续过渡不跳变

无法解析: 55
```

**为什么用双向覆盖率而非 IoU**：求职者期望 25-28K、岗位给 20-35K，IoU 只有 3/15=0.2，但求职者的期望被**完全满足**——覆盖率 = 3/3 = 1.0 → 92 分，更符合招聘直觉。

## 4. 严格化调整项（区分人才的关键）

五维加权总分之外，`calc_adjustments()` 叠加 5 个调整项（可正可负）：

| 调整项 | 触发条件 | 分值 | 设计意图 |
|---|---|---|---|
| `core_skill_penalty` | 每缺失 1 个核心技能 | **−8/个** | 核心技能硬门槛，缺核心直接重罚 |
| `ecosystem_bonus` | 匹配率>0.85 且技能数≥5 | **+5** | 技能生态链完整（次级匹配率>0.7 且≥3 技能给 +2） |
| `exp_skill_consistency` | 经验≥3年但技能<3个 | **−6** | 疑似简历注水/能力单一 |
| | 经验<1年但技能>15个 | **−4** | 疑似虚标技能 |
| `red_flag_penalty` | 任一维度 <30 分 | **−10** | 红旗：存在严重不匹配短板 |
| `balance_bonus` | 五维标准差 <8 | **+3** | 全面均衡（<15 给 +1） |

最终分数：

```
final = clamp(基础加权分 + Σ调整项, TOTAL_FLOOR=15, TOTAL_CEIL=95)
```

## 5. 池内归一化（v3 新增）

**动机**：绝对分只回答"候选人 vs 岗位要求"，不回答"候选人在同一岗位候选人池里排第几"。两个 75 分的人，一个是池内第一、一个是池内垫底，对 HR 意义完全不同。

**算法**（`apply_pool_normalization`，对每个岗位的候选人池）：

```
z      = (score − mean) / stdev          ← 标准化
adjust = tanh(z) × 6                     ← tanh 压缩，天然有界 ±6
final  = clamp(score + adjust, 15, 95)
```

**为什么选 tanh(z) 而不是别的**：

| 方案 | 问题 |
|---|---|
| 直接加 z | 无界，一个 95 分离群值会把全池其他人压到地板 |
| percentile | 只保留名次、丢弃分差——第 1 名领先 20 分和领先 2 分结果相同 |
| **tanh(z)** | **有界 + 平滑 + 保留分差信息** |

**生效条件**：池规模 ≥3（`POOL_MIN_SIZE`）且 stdev>0，否则跳过（小池/无区分度不调整）。

## 6. 反馈闭环：权重校准（v3 新增）

**动机**：固定权重是拍脑袋的先验。HR 每天的 accept/reject 决策是最真实的标注数据，应该反过来校准权重。

**算法**（`calibrate_weights_from_feedback`，维度区分度法 Discriminative Gap Method）：

```
① 取 status ∈ {accepted, rejected} 的 match_records
② 对每个维度 d 计算区分度分差:
      Δd = mean(accepted_d) − mean(rejected_d)
③ 归一化: Δnorm = Δd / max|Δ|   → [−1, 1]
④ 乘法更新: w' = w × (1 + λ·Δnorm)，λ = 0.3（学习率）
⑤ 裁剪 w' ≥ 0.01（防归零）→ 归一化 Σw' = 1
```

**直觉解释**：如果 HR 接受的候选人在"技能"维度平均 85 分、拒绝的平均 60 分（Δ=25），而"学历"维度两组只差 3 分——说明该企业的决策实际重技能、轻学历，权重就朝这个方向调。

**安全设计**：
- 样本门槛：accepted、rejected 各需 ≥6 条（`CALIB_MIN_SAMPLES`），小样本噪声不进权重
- 学习率 0.3：单次校准最多让权重温和偏移，不会剧烈震荡
- 进程内生效（`_active_weights`），服务重启自动回到默认权重——校准坏了一键恢复
- 权重恒归一化到 Σ=1，总分始终在 0-100 量纲

## 7. 技能门槛过滤（Skill Gate）

在阶段①之前执行（`has_skill_overlap`）：

- 岗位要求的技能与求职者技能**完全无交集**（含同义词）→ 不创建匹配记录
- 岗位无技能要求 → 不设门槛，允许所有人匹配

目的：把"零相关性配对"挡在评分体系外，匹配列表里不出现纯噪音。

## 8. 参数速查表

| 参数 | 值 | 含义 |
|---|---|---|
| `FLOOR` / `CEIL` | 20 / 92 | 单维度分数下限/上限 |
| `TOTAL_FLOOR` / `TOTAL_CEIL` | 15 / 95 | 总分下限/上限 |
| `WEIGHTS` | .40/.20/.15/.15/.10 | 五维默认权重（技能/经验/学历/地域/薪资） |

| `POOL_MIN_SIZE` | 3 | 池内归一化最少池规模 |
| `CALIB_MIN_SAMPLES` | 6 | 反馈校准每类最少样本数 |
| `CALIB_LEARNING_RATE` | 0.3 | 权重校准学习率 λ |
| 核心技能增益 | ×2.0 | 前 1/3 技能权重翻倍 |
| 核心技能缺失惩罚 | −8/个 | 硬门槛 |
| 经验欠配 σ | lo/3 | 能力不足快速衰减 |
| 经验超配 σ | (hi−lo)/2 | overqualified 宽容衰减 |
| 薪资无重叠 σ | 10K | 薪资差距高斯衰减 |

## 10. 理论依据汇总

| 算法 | 来源领域 | 在本引擎中的用途 |
|---|---|---|
| TF-IDF | 信息检索 | 稀有技能匹配价值高于大众技能 |
| 高斯衰减 | 概率论/核方法 | 经验、薪资偏差的平滑惩罚（无硬截断） |
| 双向覆盖率 | 区间数学 | 薪资区间包含关系的直觉化度量 |
| MCDM 加权决策 | 运筹学 | 五维分数融合为总分 |
| Z-score 标准化 | 统计学 | 池内相对定位 |
| tanh 压缩 | 神经网络激活函数 | 把无界 z 压缩为有界调整量 |
| 判别式差距法 | 本项目设计 | HR 反馈驱动的权重在线学习 |
