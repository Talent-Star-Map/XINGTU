## 三、Agent 设计与工作流

### 3.1 Agent 总览

| Agent 名称 | 用途 | 输入 | 输出 | 调用频率 |
|---|---|---|---|---|
| **数据采集 Agent** | 从多源爬取 JD 数据 | 采集配置（源URL、关键词） | 结构化 JD 数据 | 定时（每天） |
| **JD 解析 Agent** | 从 JD 文本提取技能和结构化信息 | JD 原始文本 | 技能列表 + 置信度 | 每采集一条调一次 |
| **质检 Agent** | 交叉验证、幻觉防控、抄袭/通胀检测 | JD 解析结果 + 多个数据源 | 验证后的技能列表 + 异常标记 | 解析后自动触发 |
| **趋势分析 Agent** | 发现新岗位 + 检测既有岗位变化 | 历史 JD 数据 + 新数据 | 新岗位定义 + 变化报告 | 定时（每天/每周） |
| **匹配分析 Agent** | 简历与岗位的匹配度分析 | 简历技能 + 岗位技能 | 匹配分数 + 差距列表 | 用户触发 |
| **学习路径 Agent** | 生成岗位学习计划 | 差距分析结果 + 目标岗位 | 分阶段学习路径 | 用户触发 |

### 3.2 核心工作流一：定时数据采集→分析→更新

```
定时触发（每天凌晨 2 点）
  │
  ▼
┌─────────────────────────────────────┐
│ 数据采集 Agent                       │
│  ├─ 爬 Boss 直聘（关键词：AI/Java/大数据...） │
│  ├─ 爬 拉勾（同上）                            │
│  └─ 爬 GitHub Jobs（技术趋势）                 │
│                                        │
│ 输出：原始 JD 文本（多个来源）                    │
└──────────────────────┬──────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────┐
│ JD 解析 Agent                        │
│  ├─ 调用 DeepSeek API 提取技能         │
│  ├─ 标准化技能名称                     │
│  └─ 输出每个技能的置信度评分            │
│                                        │
│ 输出：结构化技能列表 + 置信度                │
└──────────────────────┬──────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────┐
│ 质检 Agent（创新核心）                │
│                                      │
│ ① 多源交叉验证：                       │
│    同一技能在 ≥2 个来源出现 → 可信      │
│    同一技能只在 1 个来源出现 → 低置信度   │
│                                      │
│ ② 抄袭检测：                          │
│    JD 相似度 > 90% → 标记为疑似抄袭    │
│                                      │
│ ③ 通胀检测：                          │
│    同岗位技能要求偏离均值太多 → 标记     │
│                                      │
│ ④ 幻觉防控：                          │
│    每个技能附带"原文依据"               │
│    不符合交叉验证的技能不收录           │
│                                      │
│ 输出：已验证的技能列表 + 异常标记           │
└──────────────────────┬──────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────┐
│ 趋势分析 Agent                       │
│                                      │
│ ① 新岗位发现：                         │
│    对比历史数据 → 发现"从0到N"的岗位     │
│    语义聚类 → 合并相似岗位名            │
│    生成新岗位定义（名称/职责/技能/场景）   │
│                                      │
│ ② 既有岗位更新：                       │
│    对比新旧 JD → 标注新增/删除/修改的技能  │
│    生成更新说明 + 数据源标注             │
│                                      │
│ 输出：新岗位定义 + 既有岗位更新报告          │
└──────────────────────┬──────────────────────┘
                       │
                       ▼
              更新数据库 + 图谱
```

### 3.3 核心工作流二：用户触发的人岗匹配

```
用户上传简历（PDF/Word）
  │
  ▼

  │
  ▼
JD 解析 Agent（复用）→ 提取简历中的技能
  │
  ▼

  │
  ▼
┌─────────────────────────────────────┐
│ 匹配分析 Agent                       │
│                                      │
│ ① 技能匹配：简历技能 ∩ 岗位技能         │
│ ② 经验匹配：工作年限对比               │
│ ③ 学历匹配：学历要求对比               │
│ ④ 综合评分 + 匹配理由                  │
│                                      │
│ 输出：匹配分数 + 差距列表 + 匹配理由        │
└──────────────────────┬──────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────┐
│ 学习路径 Agent                       │
│                                      │
│ 输入：差距列表（缺什么技能）            │
│ 输出：                              │
│   ├─ 阶段 1：基础入门（1-2 周）        │
│   ├─ 阶段 2：进阶实践（2-4 周）        │
│   ├─ 阶段 3：深入掌握（4-8 周）        │
│   └─ 推荐学习资源（课程/文档/项目）      │
└──────────────────────┬──────────────────────┘
                       │
                       ▼
            返回前端展示匹配结果
```

## 四、多源异构数据方案

### 4.1 数据来源

| 来源 | 数据类型 | 采集方式 | 用途 |
|---|---|---|---|
| **Boss 直聘** | 岗位 JD、技能要求、薪资 | 爬虫 | 核心 JD 数据 |
| **拉勾** | 岗位 JD、技能要求、薪资 | 爬虫 | 交叉验证数据 |
| **GitHub Jobs** | 技术岗位、技能趋势 | 爬虫 | 趋势分析、交叉验证 |
| **技术博客/社区** | 技术文章、技能讨论 | 爬虫 | 趋势验证 |

### 4.2 交叉验证逻辑

```
技能 "Kubernetes" 出现情况：

来源 A（Boss直聘）："要求熟悉 Kubernetes"  →  ✅
来源 B（拉勾）："需要 K8s 经验"            →  ✅（K8s = Kubernetes）
来源 C（GitHub）：项目使用 Kubernetes      →  ✅

结论：3 个独立来源都验证了 → 置信度 95% → 收录

---

技能 "区块链" 出现情况：

来源 A（Boss直聘）："熟悉区块链技术"      →  ✅
来源 B（拉勾）：未出现                     →  ❌
来源 C（GitHub）：未涉及                   →  ❌

结论：只有 1 个来源 → 置信度 40% → 标记为"待确认"
```

## 五、数据库设计（核心表）

### 5.1 岗位表（jobs）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGSERIAL | 主键 |
| title | VARCHAR(200) | 岗位名称 |
| source | VARCHAR(50) | 数据来源（boss/lagou/github） |
| source_url | VARCHAR(500) | 原始 URL |
| description | TEXT | JD 原始文本 |
| skills | JSONB | 提取的技能列表 |
| function_type | VARCHAR(100) | 职能分类 |
| salary_min / salary_max | INT | 薪资范围 |
| education | VARCHAR(50) | 学历要求 |
| experience | VARCHAR(50) | 经验要求 |
| collected_at | TIMESTAMP | 采集时间 |
| created_at / updated_at | TIMESTAMP | 创建/更新时间 |

### 5.2 技能标签表（skill_tags）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | SERIAL | 主键 |
| name | VARCHAR(100) | 技能名称 |
| category | VARCHAR(50) | 分类（语言/框架/工具/数据库） |
| synonyms | JSONB | 同义词列表 |

### 5.3 图谱关系表（graph_edges）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGSERIAL | 主键 |
| source_type | VARCHAR(20) | 源节点类型（job/skill） |
| source_id | INT | 源节点 ID |
| target_type | VARCHAR(20) | 目标节点类型（job/skill） |
| target_id | INT | 目标节点 ID |
| relation | VARCHAR(50) | 关系类型（requires/related_to） |
| weight | FLOAT | 关系权重（0-1） |
| period | VARCHAR(20) | 时间段（用于追踪变化） |

## 六、Agent 与业务逻辑的边界划分

| 用 DeerFlow-Harness 做的（Agent） | 自己写代码做的（传统逻辑） |
|---|---|

| 管理对话上下文 | 数据库 CRUD |

## 九、架构设计原则

| 原则 | 说明 |
|---|---|
| **Agent 只管 AI 相关** | 登录、注册、简单查询不走 Agent，直接 SQL |
| **数据先行** | 先保证 100 条测试数据的标注和采集，再开发功能 |
| **链路优先** | 先跑通全流程（采集→解析→匹配→展示），再优化每个环节 |
| **轻量部署** | 只用 2 个 Docker 服务（web + db），不用消息队列等中间件 |
