# 仓库敏感信息整改

本次处理仅修改仓库，不代表生产密码已更换，也不改变现有服务器网络规则。

- `.env` 仅保存在运行环境，复制 `.env.example` 后自行填写，不通过 Git 共享。
- 已公开的数据库密码、JWT 密钥、邮箱授权码、AI 密钥均应视为泄露；由凭据所有者在对应服务中撤销并重新生成。JWT 更换后原登录会话失效。
- 历史清理会改变提交编号。协作者应先备份未提交工作，再重新克隆；不得把旧分支或旧备份直接推回。
- GitHub PR 引用、缓存、其他人的克隆和分叉不能通过分支推送清除；涉及敏感提交的 PR/缓存应联系 GitHub Support 处理。
- 本地原始备份含旧秘密，仅用于恢复，禁止上传或分享。

## 数据库受控访问

仓库的 MySQL Compose 默认仅绑定 `127.0.0.1:3308`。容器内服务使用 Docker 内网数据库地址；远程维护使用 SSH 隧道或 VPN。
Neo4j（7474/7687）和 MongoDB（27017）不由当前主项目 Compose 管理，部署方需在其配置及防火墙中限制为内网或回环地址。
修改仓库中的 Compose 不会自动改变已运行容器；线上生效需要单独部署及网络验证。

## 发布前检查

执行 `python scripts/check_repository_secrets.py`。检测只输出文件和行号，不输出凭据值。
