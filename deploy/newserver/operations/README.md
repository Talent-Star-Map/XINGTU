# 服务器维护与部署记录

团队先看 [最后一次验证的状态](STATUS.md)，再查 [公网 HTTPS 记录](records/20261023_public_https.md) 与 [个人图谱记录](records/20261023_personal_graph.md)。本目录只存脱敏摘要与维护约定；GitHub 推送成功不代表应用已经上线。

## 两边如何配合

| 位置 | 保存内容 | 更新方式 |
| --- | --- | --- |
| GitHub 本目录 | 实际应用版本、部署/回滚结论、重要故障与已知问题、验收概要 | 有重要变化时普通快进提交，保留历史记录 |
| 服务器 `/data/xingtu/operations/maintenance/` | `STATUS.md`、`latest.json`、每轮不可覆盖的 `history/` | 每轮维护先落盘并读回验证 |
| 服务器 `releases/<发布ID>/` | 完整构建、测试、切换和回滚私有证据 | 按发布保存，不覆盖旧发布 |
| 服务器 `/data/backups/daily/` | 数据库逻辑备份及校验清单 | 独立备份 timer；本机副本另行验证 |

维护记录 ID、发布 ID、检查时间关联两边。需要明确区分仓库提交、目标应用提交、实际运行镜像/源码提交；运维文档提交不等于应用版本变化。

## 每日流程

目前安排由本机 Codex 每天北京时间 **09:30** 在原维护聊天执行，须电脑开机、Codex 运行且本地项目可用。服务器备份与采集 timer 独立运行；不是两套无人值守部署任务，也不是 GitHub Actions 自动发布。

1. fetch 主线、采集及队友分支，检查新提交；保护本机未提交改动，不自动合并队友分支。
2. SSH 核对网页/API、六容器、三库只读连通、采集/备份结果与定时器、云盘挂载/容量/权限、Docker/containerd 存储位置。控制台未查就明确标记账单、介质和云快照未验证。
   每轮也检查 `xingtu-github-daily.timer/service` 和北京时间当天的成功榜单快照；超时失败不得写成成功或空榜。补跑须先核对现有采集实现及当天快照，保护按日不可覆盖记录，记录原失败与恢复结果。
   同时从外网核对 `https://47.120.76.16/`、IP 证书到期时间、续签 timer 和最近续签结果，以及 80 验证路径/HTTPS 跳转。配置快照及操作边界见 [公网配置](../public/README.md)。
3. 新应用先审查依赖、启动写库、SQL 和图谱兼容；使用隔离源码、无生产访问的离线测试、备份、固定回滚镜像，验证通过后更新相应应用并验收。失败回滚，禁止跳过测试强行发布。
4. **每轮先保存云盘日志**并在本机保全镜像。有部署、回滚、重要故障、待确认事项或其解决时，更新本目录 `STATUS.md` 并新增记录，再脱敏检查、普通推送、核实远端提交，将 GitHub 同步回执写回云盘。
5. GitHub 不可达则云盘记录 `PENDING`，后续重试；不能将本机提交说成已推送。远端并发更新时 fetch 并仅重放自己的文档变更，禁止强推。无实质变化不制造 Git 提交；仅运维文档变化不重建应用。

## 边界与记录要求

- 生产建表改表遵守团队手动 SQL 和先确认结构的规范；不让新采集 runner 自动 DDL 绕过确认。破坏性图谱重建、凭据轮换另需确认。
- 2026-10-23 用户明确冻结已交付队长的账号密码；后续维护禁止轮换、重置、恢复默认或执行账号种子，除非用户后续明确变更要求。公网维护与队员现有登录并行，不将密码变更作为常规发布步骤。
- 不删除数据、备份或历史发布，不擅自启用停用中的 AI 抽取，不改标注/测试/实验标准。
- 不提交 `.env`、密钥、密码、令牌、个人简历、数据库导出或未脱敏私有日志；连接凭据仍私下交付。
- 每条记录包含时间、ID、前后版本、动作、备份标识、验证结果、失败/回滚原因和未验证事项。失败和未发布也要保留，旧轮次不覆盖。
- 在线逻辑备份不是跨引擎冻结快照；手动本机副本不等于自动异地备份，未做恢复演练不能声称已验证恢复。

本地操作员的项目交接和每日维护手册仍是连接、指纹及私有路径的入口，不在仓库复制凭据。现有服务器运行目录不能重新执行空目录初始化流程。
