## 公网 Nginx 入口（已就位，未对外开放）

`nginx 1.24.0` 通过 `policy-rc.d` 阻止安装期自启后安装，随后 `disable` 并删除 `sites-enabled/default`，确认过服务 `inactive`、无 80 监听，再按团队确认启用。站点配置 `/etc/nginx/sites-available/xingtu-public.conf`：

- 只反代 `127.0.0.1:3000`（前端容器）。`/api/` 与 `/uploads/` 仍由容器内 nginx 转 `api:8081`，宿主机不再重复接 8081，以免绕过容器内已调好的流式、上传上限和日志策略。
- 自定义 `log_format` 用 `$request_method $uri $server_protocol`，**不含 query string**。本项目 JWT 走 `?token=`，默认 `combined` 的 `$request` 会把真实凭证写进 access.log。已用带 `?token=CANARY_…` 的请求实测：日志只记路径，全文件 grep 该标记为 0 命中。
- 流式：`proxy_buffering off` + `proxy_read/send_timeout 300s` + HTTP/1.1，供 `/api/chat`（`text/event-stream`）与 `/api/interview`（`application/x-ndjson`）使用。
- 上传：`client_max_body_size 10m`，与容器一致；不写会按默认 1m 把简历附件打成 413。
- 限流：`/api/auth/(login|admin/login|send-code|register)` 单 IP 1r/s burst 5，其余 30r/s burst 60。应用层当前**没有**登录失败锁定或验证码频控，这层是兜底不是替代。
- 其他：`server_tokens off`、`X-Content-Type-Options`、`X-Frame-Options SAMEORIGIN`、`Referrer-Policy`。

数据库端口未进入该配置：`compose.yaml` 里 MySQL 3308、Mongo 27017、Neo4j 7474/7687、API 8081、前端 3000 **全部绑定 `127.0.0.1`**；宿主机 `ufw` inactive，唯一对外监听原为 22。外部探测 80/443/3000/8081 均超时，确认云安全组只放行 TCP 22 —— 因此**公网开放还差控制台入方向规则这一步**，须由凭据所有者在阿里云控制台添加（建议同时预留 443；能按源 IP 段放行就不要全网 0.0.0.0/0）。
