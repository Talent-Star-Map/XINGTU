# 智能问答补充材料

智能问答输入区支持最多 4 个文件，每个不超过 10MB：PDF（文字层，最多 50 页）、DOCX（段落及表格）、TXT、Markdown、CSV、PNG、JPEG、WebP。

材料仅用于当前页面对话。文档每份最多使用前 12000 字，截断会显示提示。扫描 PDF 暂不自动 OCR，可将相关页面作为图片上传。图片在服务器缩放到最长边 1600 像素后交给视觉模型阅读，因此不能保证识别很小的文字。

上传只解析文档或规范化图片，不调用外部模型。点击发送问题后，文档文本和图片会交给系统配置的对应模型。当前材料用于后续追问；移除材料后，新提问不再附带该材料。旧消息的重试仍使用该消息原来的材料，直到材料过期。切换岗位或新建对话会清空材料选择。

临时内容保存在系统临时目录中的 `xingtu-chat-private-*`，不在公开文件目录内，也不写业务数据库。记录按登录角色及用户 ID 隔离，有效期一小时。上传及读取时清理过期文件；运维可以定期清理该目录以处理长时间无访问的实例。多个 worker 必须使用同一个临时目录；多主机部署需改为有 TTL 的共享私有对象存储。

图片理解复用管理员模型配置中的 `vision_model`、`vision_base_url`、`vision_api_key`（OpenAI 兼容的图文消息接口）。三项缺失时返回明确提示，不使用文字模型冒充图片理解。不自动安装模型，不更改管理员现有配置。文档问答继续使用现有智能问答模型。

这版没有接入 CLIP，也没有建立图片作品库。CLIP 适合后续的“用文字搜索已保存图片”：先提供独立、用户授权保存的作品库，再用同一 CLIP 编码器分别编码图片与检索文字，按相似度检索，并按用户权限过滤。图片理解和图文检索是两项能力，不能把附件上传称为已实现 CLIP。

离线检查：`python backend/tests/test_chat_materials.py`、`node --test frontend/tests/chatStream.test.mjs`。测试用生成文件和模拟模型，不发送真实用户材料。
